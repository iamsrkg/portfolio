Edge

Nginx terminates TLS, stamps a request ID and proxies to a container that took three minutes to ship.

  • Tag it at the door. A request ID added at the edge lets one log search follow a request through every service.
  • Small images ship faster. Multi-stage Docker builds keep the toolchain out of production, and fast deploys get shipped more often.

where I built this

Freelance · 2025–26: Docker multi-stage builds behind Nginx took deploys from 20 minutes to 3.

Accenture · 2021–24: Azure DevOps pipelines that build, test and ship Docker images to Kubernetes.

hop 02t+2ms

Rate limiter

Before anything expensive happens, the request spends a token. No token, no entry, and a clear note on when to come back.

  • Reject cheaply first. A request that's going to be refused should never reach the password hasher or the database.
  • Say when to retry. 429 with Retry-After turns a flood into an orderly queue, and I honour it when I'm the client too.

where I built this

Freelance · 2025–26: rate limiting and IP throttling in front of auth and the client APIs.

Public · task-management-api: a token-bucket filter that answers 429 with Retry-After, tested in CI.

hop 03t+5ms

Auth

The token is checked, not trusted: signature first, then expiry, then role. One service issues tokens and everyone else only verifies them.

  • Security code in one place. Splitting auth from business logic means one small surface to review, and changes stop rippling across the codebase.
  • Two questions, two layers. RBAC decides whether you may call the route, and ownership decides whether you may touch the row.

where I built this

Freelance · 2025–26: auth as its own service with JWT, RBAC, granular permissions, encryption and audit logs, which meant 60% less coupling.

Accenture · 2021–24: Spring Security with JWT and role-based access on every endpoint.

Cache & database

            
Hot reads come from the cache. Everything else hits an index, never a full table scan.

          

          

            

              
    
                
  • Fix the plan before buying hardware. Most slow APIs are one missing composite index away from fast.
    • 
                
  • Cache on purpose. Cache what's read often and changes rarely, and know exactly what invalidates it.
    • 
                
  • History is data. Type-2 versioning keeps every change as a row, so audit trails come free.
    •

# Find every Team with no owner. Graph pages its results, so follow nextLink.
$uri = 'https://graph.microsoft.com/v1.0/groups?$select=id,displayName' +
       '&$filter=resourceProvisioningOptions/Any(x:x eq ''Team'')'
$report = do {
  $page = Invoke-MgGraphRequest -Uri $uri
  foreach ($g in $page.value) {
    $owners = Invoke-MgGraphRequest -Uri "https://graph.microsoft.com/v1.0/groups/$($g.id)/owners"
    if (-not $owners.value) { [pscustomobject]@{ Team = $g.displayName; Id = $g.id } }
  }
  $uri = $page.'@odata.nextLink'
} while ($uri)

example · Type-2 versioning in SQL


-- An edit never overwrites: it closes the current row and adds a new one.
UPDATE page_versions
   SET valid_to = now(), is_current = false
 WHERE page_id = $1 AND is_current;

INSERT INTO page_versions (page_id, body, edited_by, valid_from, is_current)
VALUES ($1, $2, $3, now(), true);

-- "What did this page say on 1 Feb, and who changed it?"
-- is now a query, not a backup restore.
SELECT body, edited_by FROM page_versions
 WHERE page_id = $1
   AND valid_from <= '2026-02-01'
   AND (valid_to IS NULL OR valid_to > '2026-02-01');

    The filter chain: stateless JWT auth, JSON 401/403 instead of Spring's default 403, and the cheapest checks first.
    
              
    
                
    SecurityConfig.java · lines 51–77view on GitHub ↗
    

    @Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    http
            .csrf(AbstractHttpConfigurer::disable)
            .cors(Customizer.withDefaults())
            .authorizeHttpRequests(req -> req
                    .requestMatchers("/api/auth/**", "/actuator/health", "/actuator/health/**").permitAll()
                    .anyRequest().authenticated()
            )
            .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            // Without these, Spring answers a missing/invalid token with 403; the correct status is 401.
            .exceptionHandling(ex -> ex
                    .authenticationEntryPoint((request, response, e) ->
                            JsonErrorWriter.write(response, 401, "Authentication required: missing, invalid or expired token."))
                    .accessDeniedHandler((request, response, e) ->
                            JsonErrorWriter.write(response, 403, "Access denied: You do not have the required role."))
            )
            .authenticationProvider(authenticationProvider)
            .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class);

    // Cheapest checks first: tag the request, then rate limit, then authenticate.
    if (rateLimitEnabled) {
        http.addFilterBefore(new RateLimitFilter(rateLimitCapacity, rateLimitRefillPerSecond), JwtAuthenticationFilter.class);
        http.addFilterBefore(new RequestIdFilter(), RateLimitFilter.class);
    } else {
        http.addFilterBefore(new RequestIdFilter(), JwtAuthenticationFilter.class);
    }

    @Transactional
public TaskResponseDTO updateTask(UUID taskId, TaskRequestDTO request, User authenticatedUser) {
    if (request.getVersion() == null) {
        throw new IllegalArgumentException("version is required when updating a task (optimistic locking)");
    }

    Task task = findVisible(taskId, authenticatedUser);
    requireOwner(task, authenticatedUser, "Only the project owner can edit this task");

    if (!request.getVersion().equals(task.getVersion())) {
        throw new ObjectOptimisticLockingFailureException(Task.class, task.getId());
    }

    A token bucket per client in a servlet filter: thread-safe per bucket, idle buckets evicted, and a Retry-After header on 429.
    
              
    
                
    RateLimitFilter.java · lines 36–72view on GitHub ↗
    

    protected void doFilterInternal(
        @NonNull HttpServletRequest request,
        @NonNull HttpServletResponse response,
        @NonNull FilterChain filterChain
) throws ServletException, IOException {
    if ("OPTIONS".equalsIgnoreCase(request.getMethod())) {
        filterChain.doFilter(request, response);
        return;
    }
    if (buckets.size() > MAX_TRACKED_CLIENTS) {
        long now = System.nanoTime();
        buckets.values().removeIf(b -> now - b.lastRefill > IDLE_EVICTION_NANOS);
    }

    Bucket bucket = buckets.computeIfAbsent(request.getRemoteAddr(), k -> new Bucket(capacity));
    long remaining;
    long retryAfterSeconds = 0;
    boolean allowed;
    synchronized (bucket) {
        bucket.refill(capacity, refillPerSecond);
        allowed = bucket.tokens >= 1;
        if (allowed) {
            bucket.tokens -= 1;
        } else {
            retryAfterSeconds = (long) Math.ceil((1 - bucket.tokens) / refillPerSecond);
        }
        remaining = (long) Math.floor(bucket.tokens);
    }

    response.setHeader("X-RateLimit-Limit", String.valueOf(capacity));
    response.setHeader("X-RateLimit-Remaining", String.valueOf(remaining));
    if (!allowed) {
        response.setHeader("Retry-After", String.valueOf(Math.max(1, retryAfterSeconds)));
        JsonErrorWriter.write(response, 429, "Too many requests. Retry after " + Math.max(1, retryAfterSeconds) + "s.");
        return;
    }
    filterChain.doFilter(request, response);
